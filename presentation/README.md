## 2. 목차 & 시간 배분 (약 13분: 발표 10분 + 데모 3분)

| # | 섹션 | 시간 | 발표자 | 한 줄 |
|---|------|:---:|:---:|------|

## 3. 배치 전략 (어디에 힘을 주나)

1. **데모를 앞쪽(3번 뒤)에.** 이론 먼저 깔면 비전공자는 지친다 → 먼저 보여주고 "이게 어떻게 되는지" 설명.
2. **시간의 절반을 데모 + 하이브리드 추천(7번)에.** 나머지는 빠르게.
3. **7번이 하이라이트:** *"로션 추천해줘 → AI가 크림 추천"* 실패 한 컷 → 왜(의미만 비슷한 걸 고름) → 해결(SQL이 조건 거름 + AI가 취향 정렬) → 증명(✓/✗ 배지). 실패 리포트가 그대로 근거.
4. **슬라이드는 글자 최소, 화면 캡처·다이어그램 위주.**

## 4. 라이브 데모 스크립트 (3분)

> 슬라이드 없이 실제 화면. FE가 운전, 추천 결과가 뜨는 순간 BE가 한마디 얹는다.

```
① 로그인(카카오)              → "비밀번호 저장 안 하고 카카오에 확인 위임"
② 온보딩(피부 타입·고민)       → 프로필이 추천에 자동 반영
③ 챗봇: "지성 피부, 2~3만원대 크림 추천해줘"
④ 추천 3개 + 이유 + ✓가격/✓제형 배지   ← [BE] "여긴 SQL로 조건 거르고 AI로 정렬한 결과예요"
⑤ 제품 상세(AI 요약·피부타입별 만족도) → 찜
⑥ 커뮤니티: 글 보기 + 제품 태그 → 댓글/좋아요
⑦ 마이페이지: 찜·추천 내역
```

### ⚠️ 라이브 안전장치 (필수)
- **백업 녹화 영상** 준비 — 끊기면 즉시 전환.
- 발표 직전 **추천 1회 미리 호출**(LLM 세션 워밍업) + 쓸 쿼리 결과 확인.
- **미리 로그인된 계정 + 시드 데이터** 세팅, 데모 쿼리 고정.
- 추천 응답 대기(수 초) 동안 **로딩 화면(스켈레톤)을 디자인 포인트로** 멘트.

## 5. 슬라이드 만들 때 톤
- 한 슬라이드 = 한 메시지. 글머리표 3~5개 이내.
- 전문용어는 슬라이드에 쓰지 말고 **입으로 쉽게 풀기**(대본의 🎤 참고).
- 보태니컬 톤(크림색·세리프) 유지 → 발표 자료도 제품 정체성.
