# GMS 모델 선정 보고서

> 응답 지연 개선 + 크레딧 활용(30,000 중 ~2,800만 사용, 6/26 소멸)을 계기로
> 생성·임베딩 모델을 실측 비교해 **가장 합리적인 조합**을 정한다.
> 작성: 2026-06-24 · 관련: [chatbot-quality-troubleshooting.md](chatbot-quality-troubleshooting.md) §6

---

## 1. 측정 방법

- 동일한 추천 프롬프트(필터된 후보 15개 + "지성 2~3만원대 선크림")와 대화 프롬프트로 모델만 교체.
- 측정: 추천 LLM 지연 · 대화 LLM 지연 · 추천 이유 품질(샘플) · 크레딧/호출.
- gpt-5 계열은 `reasoning_effort=low` 적용, gpt-4 계열은 미적용(비추론).
- ⚠️ 각 1회 측정(n=1)이라 ±1~2s 변동 있음. 추세 판단용.

## 2. 생성 모델 비교

| 모델 | 추천 지연 | 대화 지연 | 이유 품질 | 추론 | 크레딧/호출 |
|------|-----------|-----------|-----------|------|-------------|
| gpt-5-nano *(현재)* | 9.1s | 4.2s | 일반적("무기자차로 백탁 낮고…") | Y | 1 |
| gpt-5-mini | 7.7s | 8.2s | 좋음(서술적) | Y | 5 |
| gpt-4o-mini | 4.7s | 1.7s | 좋음·**제품명 명시** | N | 2 |
| **gpt-4o** | **3.6s** | **1.2s** | **좋음·구체적** | N | 20 |
| gpt-4.1 | 7.1s※ | 1.1s | 좋음·구체적 | N | 16 |

※ gpt-4.1 추천 7.1s는 변동으로 추정(대화는 1.1s로 가장 빠름).

### 핵심 발견
1. **비추론(gpt-4o/4.1/4o-mini)이 추론(gpt-5.x)보다 2~3배 빠르다.** 추론 모델은 `reasoning_effort=low`를 줘도 숨은 추론 오버헤드가 남는다.
2. **비추론 모델의 추천 이유가 더 구체적**이다 — 제품명을 명시하며 근거를 댄다. nano는 일반적 표현에 그침.
3. **gpt-4o가 속도·품질 모두 1위.** gpt-4o-mini는 거의 동급에 비용은 1/10.

## 3. 임베딩 모델

| 모델 | 차원 | 호출 | 비고 |
|------|------|------|------|
| text-embedding-3-small *(현재)* | 1536 | ✅ 200 | 현행 |
| text-embedding-3-large | 3072 | ✅ 200 | 차원 달라 마이그레이션+전체 재백필 필요 |
| gemini-embedding-2 | — | ❌ 404 | **GMS 미제공** |
| gemini-embedding-001 | — | ❌ 400 | **GMS 미제공** |

→ **gemini 임베딩은 GMS에서 호출 불가**(404/400). 유일한 업그레이드 후보는 `3-large`인데:
- 차원 1536→3072 변경 = `Product.embedding` VectorField 마이그레이션 + **전체 재백필**(제품·쿼리 같은 모델이어야 코사인이 유효).
- **ROI 낮음**: SQL 필터가 하드 제약을 이미 처리하고, 카탈로그가 ~100개라 검색 정밀도 이득이 작다.
- (3-large를 `dimensions=1536`로 호출하면 마이그레이션 없이 재백필만으로도 가능하나, 이득 대비 작업이 큼.)

## 4. 권장 조합

| 용도 | 권장 | 이유 |
|------|------|------|
| **생성(대화+추천)** | **gpt-4o** | 속도·품질 모두 1위. 크레딧 충분(소멸 임박) → 품질에 투자 |
| 가성비 대안 | gpt-4o-mini | 거의 동급, 비용 1/10. 크레딧 아끼려면 |
| **임베딩** | **text-embedding-3-small 유지** | gemini 불가, large는 ROI 낮음 |

> 대화·추천에 **다른 모델**을 쓰는 분리도 가능하나(예: 대화 4o-mini / 추천 4o), 모델별 호출 코드가 필요하다. 단일 `gpt-4o`가 둘 다 충분히 빠르고 좋아 **하나로 통일**을 권장.

## 5. 적용 방법

`.env`:
```
GMS_MODEL=gpt-4o
```
- `reasoning_effort`는 코드가 **비추론 모델엔 자동으로 안 보낸다**(_call_gms 가드). `GMS_REASONING_EFFORT`는 그대로 둬도 안전.
- **되돌리기:** `GMS_MODEL=gpt-5-nano` (즉시 원복, 코드 변경 0).

### 크레딧 영향
- gpt-4o = 20 credit/호출. 남은 ~27,000 → 약 **1,350회**(추천+대화). 6/26 소멸 전 demo·평가 품질↑에 사용.
- 소멸 후 새 크레딧이 같은 규모면 gpt-4o도 지속 가능(1500회 수준). pro급(540)만 피하면 됨.

## 6. 결론

- **생성 모델을 `gpt-4o`로 교체** → 지연 67%↓(추천 24s→4s 수준)·품질↑·크레딧 활용.
- 임베딩은 현행 유지(업그레이드 경로가 막혀 있고 ROI 낮음).
- 모든 변경이 `.env` 한 줄이라 **리스크·되돌림 비용 0**.
