# 04. 데이터 확보와 정제

## ① 한 줄 요약

올리브영의 화장품 제품과 리뷰를 직접 모아, AI로 요약·정리하고, 누구나 한 번에 불러올 수 있는 초기 데이터 파일로 다듬은 과정입니다. **올리브영 제품 306종**을 수집하고, 중복을 골라내고 요약을 채우는 **정제 파이프라인**을 거쳐 추천 서비스의 토대 데이터로 확보했습니다.

> 용어 풀이
> - **크롤링** = 웹페이지를 자동으로 돌아다니며 필요한 정보를 긁어오는 것.
> - **리뷰** = 제품을 산 사람들이 남긴 후기.
> - **AI 요약(LLM)** = 사람이 쓴 글을 인공지능이 짧고 핵심만 추려 정리하는 것.
> - **fixture(픽스처)** = 데이터베이스를 한 번에 채워 넣는 초기 데이터 파일.

---

## ② 무엇을 했나

추천 서비스가 동작하려면 먼저 **제품 데이터**가 있어야 합니다. 이 데이터를 만들기까지 네 단계를 거쳤습니다.

| 단계 | 한 일 | 쉽게 말하면 |
|------|-------|-------------|
| 1. 수집 | 올리브영에서 제품 정보와 리뷰를 크롤링 | 웹사이트를 자동으로 돌며 제품·후기를 긁어옴 |
| 2. AI 가공 | 리뷰를 AI로 요약하고, 피부타입별 만족도를 정리 | 길고 많은 후기를 짧은 핵심 요약으로 바꿈 |
| 3. 정제 | 중복 제거, 빠진 요약 채우기, 가격·카테고리 점검 | 잘못되거나 겹친 데이터를 깔끔히 정리 |
| 4. fixture화 | 정리된 데이터를 초기 데이터 파일로 저장 | 명령어 한 줄로 DB를 채울 수 있게 포장 |

각 단계를 조금 더 풀면 다음과 같습니다.

**1. 수집** — `backend/crawling.py`에서 자동화 도구(Selenium / undetected-chromedriver, 사람처럼 브라우저를 움직여 정보를 가져오는 도구)로 올리브영의 4개 카테고리(스킨케어·클렌징·선케어·메이크업) 제품과 리뷰를 모았습니다.

**2. AI 가공** — 모은 리뷰를 AI(GMS)로 요약해 제품마다 한두 문장짜리 `ai_summary`를 만들고, "지성에 좋아요", "건성에 좋아요" 같은 만족도 정보를 피부타입별로 정리한 `satisfaction_by_type`를 만들었습니다. 이 요약은 나중에 추천 기능이 제품을 찾을 때 쓰는 **검색 재료**가 됩니다.

**3. 정제** — 같은 제품이 여러 번 들어온 중복을 지우고, 요약이 비어 있던 제품을 채우고, 가격·카테고리가 맞는지 점검했습니다. (자세한 기록: `docs/data-cleanup.md`)

**4. fixture화** — 정리한 결과를 `products_seed.json`(제품), `board_seed.json`(게시판) 파일로 저장했습니다.

## ③ 왜 이렇게 했나 (선택지 비교)

### 데이터를 어디서 가져올까 — 공개 API vs 직접 크롤링

| 선택지 | 장점 | 단점 | 결정 |
|--------|------|------|------|
| 공개 API 사용 | 손쉽게 정해진 데이터를 받음 | 화장품·리뷰에 딱 맞는 데이터를 주는 곳이 마땅치 않음 | ✗ |
| **직접 크롤링** | 화장품 도메인에 맞는 제품·리뷰를 직접 확보 | 직접 만들어야 해 손이 더 감 | ✓ 선택 |

추천 서비스의 핵심은 "화장품을 골라주는 것"이라, 화장품과 그 후기가 풍부히 담긴 데이터가 꼭 필요했습니다. 기성 공개 API로는 이런 데이터를 얻기 어려워, **올리브영을 직접 크롤링**하는 길을 택했습니다.

### 리뷰를 어떻게 쓸까 — 원문 그대로 vs AI 요약

| 선택지 | 장점 | 단점 | 결정 |
|--------|------|------|------|
| 리뷰 원문 그대로 사용 | 가공이 필요 없음 | 양이 많고 잡음(광고·반복)이 섞여 추천 근거로 쓰기 무거움 | ✗ |
| **AI로 요약해서 사용** | 핵심만 남아 가볍고, 추천 근거로 쓰기 좋음 | 요약을 만드는 단계가 추가됨 | ✓ 선택 |

리뷰는 수천 개에 달하기도 해 그대로 쓰면 처리 비용(토큰)이 크고 잡음이 많습니다. AI로 한두 문장 요약을 만들면 **가볍고 깔끔한 추천 근거**가 되어, 이 방식을 택했습니다.

### 데이터 윤리 — 가져와도 되는지 먼저 확인

크롤링 전에 올리브영의 **robots.txt(어떤 페이지를 자동 수집해도 되는지 알려주는 규칙 파일)**와 이용 조건을 확인하고, 허용 범위 안에서만 수집했습니다. 데이터를 모으는 일에도 지켜야 할 선이 있다는 점을 고려한 것입니다.

## ④ 어떻게 작동하나

### 수집 → 가공 → 적재 파이프라인

```
[1] 수집        올리브영 크롤링 (Selenium/undetected-chromedriver)
                  └ 제품 정보(이름·브랜드·가격·URL·이미지) + 리뷰
                        │
                        ▼
[2] 가공        AI(GMS)로 리뷰 요약  →  ai_summary (한두 문장)
                피부타입별 만족도 정리 →  satisfaction_by_type (JSON)
                        │
                        ▼
[3] 적재(fixture)  정제된 데이터를 products_seed.json 으로 저장
                        │
                        ▼
                python manage.py loaddata  →  데이터베이스 한 번에 채움
```

### satisfaction_by_type는 어디에 쓰이나

`satisfaction_by_type`는 "지성·건성·민감성 등 어떤 피부타입이 이 제품에 만족했는지"를 담은 데이터입니다. 두 곳에서 쓰입니다.

- **제품 상세 화면**: 이 제품이 어떤 피부에 잘 맞는지 보여줍니다.
- **추천**: AI 요약(`ai_summary`)과 함께, 사용자의 피부타입에 맞는 제품을 골라주는 근거가 됩니다.

즉, 잘 가공한 데이터가 추천과 상세 화면 양쪽의 품질을 떠받칩니다.

## ⑤ 결과와 배운 점

### 결과

- 올리브영 제품 **306종**을 수집하고, 중복 정리·요약 백필 **정제 파이프라인**을 구축했습니다.
- 정제·요약된 제품이 추천 검색(RAG)의 대상이 됩니다.
- `products_seed.json` / `board_seed.json` 파일과 `loaddata` 명령으로 **언제든 똑같은 데이터로 환경을 재현**할 수 있습니다.

### 정제하다 만난 문제들

데이터를 다듬는 과정에서 실제로 겪은 문제와 해결입니다. (출처: `docs/data-cleanup.md`)

| 문제 | 무슨 일이었나 | 어떻게 고쳤나 |
|------|----------------|----------------|
| 중복 | 같은 제품이 카테고리마다 다른 주소로 들어와 중복 수집됨 | 제품의 진짜 고유 번호(`goodsNo`)로 묶어 대표 1건만 남기는 정제 적용 |
| 요약 누락 | 일부 제품의 AI 요약이 비어 있었음 | 리뷰를 다시 모아 AI로 요약을 백필하는 명령(`summarize_from_reviews`) 구축 |
| 가격 불일치 | DB 가격과 실제 판매 가격이 다른 경우가 있었음 | 가격·카테고리 정합성 점검으로 바로잡음 |
| URL 길이 | 올리브영 주소가 최대 298자로 길어 저장 한도(200자)를 넘김 | 저장 한도를 200 → 500자로 확대(`backend/products/models.py`의 `oliveyoung_url`) |

### 배운 점

> **양질의 데이터가 추천 품질의 토대입니다.**
> 추천이 이상하다는 제보의 진짜 원인이 추천 알고리즘이 아니라 **데이터 품질**이었던 경험이, 이 교훈을 분명히 보여줬습니다. 좋은 추천은 좋은 데이터에서 시작됩니다.

## 명세서 NF1303 충족 포인트

> NF1303 — 데이터 확보 및 `loaddata` 가능한 fixture 요건

- **데이터 확보**: 올리브영을 직접 크롤링해 화장품 도메인에 맞는 제품·리뷰 데이터를 자체 확보했습니다(제품 306종 + 중복 정리·요약 백필 파이프라인).
- **load 가능한 fixture**: `products_seed.json`, `board_seed.json`을 제공하며, `python manage.py loaddata` 명령 한 번으로 데이터베이스를 채울 수 있습니다.
- **재현성**: 같은 fixture로 누구나 동일한 초기 데이터 환경을 다시 만들 수 있습니다.
