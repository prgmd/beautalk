# 10. 배포

## ① 한 줄 요약

"내 컴퓨터에서만 돌던 프로그램"을 **인터넷의 누구나 `beautalk.site`로 접속**할 수 있게 올렸다. AWS의 작은 서버 한 대(t3.micro, 메모리 1GB) 안에 **Docker로 db·backend·nginx 세 개를 띄우고, Nginx가 교통정리**하는 구조이며, **HTTPS(자물쇠) 보안**까지 적용해 실서비스로 운영했다.

> **배포(deploy) = 다 만든 프로그램을 "항상 켜져 있는 인터넷 서버"에 올려, 아무나 접속할 수 있게 하는 것.** 개발 중에는 내 노트북이 꺼지면 아무도 못 쓰지만, 배포하면 24시간 누구나 쓸 수 있다.

---

## ② 무엇을 했나

beautalk는 크게 세 덩어리로 나뉜다.

- **프론트(화면)**: 사용자가 보는 웹페이지(Vue로 제작).
- **백엔드(두뇌)**: 데이터를 계산하고 AI 추천을 만드는 서버(Django).
- **DB(창고)**: 제품·회원·게시글 데이터를 저장하는 데이터베이스(PostgreSQL).

이 셋을 **AWS의 서버 한 대**에 올리고, 각각을 **Docker 상자(컨테이너)** 에 담아 실행했다.

> **Docker = 앱이 돌아갈 환경을 통째로 상자에 담아, 어디서나 똑같이 실행하는 기술.** "내 컴퓨터에선 되는데 서버에선 안 돼" 문제를 없애 준다.
> **Docker Compose = 여러 상자를 한 번의 명령으로 함께 켜고 끄는 지휘자.**

---

## ③ 구성도 — EC2 안의 교통정리

> **EC2 = AWS가 빌려주는 "인터넷에 항상 켜진 가상 컴퓨터" 한 대.**
> **Nginx = 들어오는 모든 인터넷 요청을 받아 "이건 화면, 저건 백엔드"로 나눠 보내는 안내데스크(리버스 프록시).**

```
                    인터넷 사용자
                        │
                  (https://beautalk.site)
                        │  443 포트(HTTPS)
                        ▼
        ┌──────────────────────────────────────────┐
        │   AWS EC2 한 대 (t3.micro · 메모리 1GB)    │
        │                                            │
        │   ┌────────────── Docker Compose ──────────┐│
        │   │                                        ││
        │   │  ① nginx (안내데스크, 64MB)            ││
        │   │      ├─ "/"         → Vue 화면(dist) 직접 보여줌
        │   │      ├─ "/api"      → ② backend 로 전달
        │   │      └─ "/admin","/static" → ② backend 로 전달
        │   │              │                         ││
        │   │              ▼                         ││
        │   │  ② backend (Django+gunicorn, 450MB)    ││
        │   │              │                         ││
        │   │              ▼                         ││
        │   │  ③ db (PostgreSQL+pgvector, 256MB)     ││
        │   │                                        ││
        │   └────────────────────────────────────────┘│
        └──────────────────────────────────────────┘
```

세 상자의 역할:

| 상자 | 무엇 | 메모리 한도 | 하는 일 |
|---|---|---|---|
| **nginx** | `nginx:alpine` | 64MB | 안내데스크. 화면은 직접 보여주고, `/api`·`/admin`·`/static` 요청은 백엔드로 넘김. HTTPS 처리 |
| **backend** | `python:3.11-slim` + gunicorn(워커 2, 타임아웃 120초) | 450MB | Django 두뇌. 외부에 직접 노출 안 되고 **nginx를 통해서만** 접근 |
| **db** | `pgvector/pgvector:pg16` | 256MB | 데이터 창고. AI 추천용 벡터 검색(pgvector)까지 지원 |

화면(Vue)은 별도 상자가 아니라, **미리 빌드해 둔 정적 파일(dist)을 nginx가 직접 서빙**한다.

## ④ 왜 이렇게 골랐나 — 선택지 비교

배포 방식에는 크게 세 갈래가 있었다. 핵심 제약은 **"메모리 1GB짜리 작은 서버 한 대"** 와 **"비용·학습 부담을 낮춰야 한다"** 였다.

| 선택지 | 어떤 방식 | 장점 | 단점 | 우리에게는 |
|---|---|---|---|---|
| **단일 EC2 + Docker Compose (채택)** | 서버 한 대에 Docker로 3개를 함께 띄움 | 저렴(서버 1대), 구성이 한눈에 보임, Docker 학습 가치 | 서버가 죽으면 전체 중단, 직접 관리 | ✅ 비용·학습·규모에 최적 |
| **관리형 PaaS** (예: Heroku류) | 클라우드가 서버를 알아서 관리 | 운영이 편함 | 비용↑, 무료 한도·제약 많음, pgvector 등 특수 설정 어려움 | ❌ 비용·제약 부담 |
| **분리형**(서버를 기능별로 여러 대) | DB·백엔드·프론트를 각각 다른 서버에 | 확장성·안정성↑ | 서버 여러 대 = 비용·관리 복잡도↑ | ❌ 우리 규모엔 과함 |

**선택 이유**: 데이터가 약 300건 규모로 작고, 트래픽도 크지 않다. 비싼 분리형이나 제약 많은 PaaS 대신, **서버 한 대에 Docker로 깔끔히 묶는 방식**이 비용·학습·규모 모든 면에서 합리적이었다. 메모리 1GB에 맞춰 **상자마다 메모리 한도를 잘게 나누고(64+450+256MB), PostgreSQL도 작게 튜닝**(`shared_buffers=128MB`, `max_connections=20`)했다.

### 왜 프론트를 EC2에서 빌드하지 않나

> **빌드(build) = 사람이 쓴 코드를 브라우저가 읽을 수 있는 최종 파일 묶음으로 변환하는 작업.** 메모리를 많이 잡아먹는다.

화면 빌드는 메모리를 크게 쓴다. **메모리 1GB짜리 작은 서버에서 빌드하면 서버가 멈출 위험**이 있다. 그래서 **빌드는 개발자의 로컬 PC나 CI(GitHub Actions)에서 미리 끝내고**, EC2에는 **완성된 결과물(dist)만 올려 nginx가 보여주게** 했다. 서버의 귀한 메모리를 백엔드·DB가 쓰도록 아낀 것이다.

### 그 밖의 운영 원칙

- **시크릿은 `.env`로 주입**: 비밀번호·키는 코드에 넣지 않고 `.env` 파일로 서버에 넣어, GitHub에는 **시크릿 0건** 커밋.
- **migrate / loaddata / backfill은 수동 실행**: DB 구조 변경·초기 데이터 적재는 자동화하지 않고 사람이 확인 후 실행 → 예기치 못한 사고 방지.

## ⑤ HTTPS — 왜 필요하고 어떻게

> **HTTP vs HTTPS**: HTTP는 정보를 **그대로(엿보기 가능)** 주고받고, HTTPS는 **암호화(자물쇠)** 해서 주고받는다. 브라우저 주소창의 자물쇠 표시가 그것이다.

beautalk는 **카카오·구글 로그인**과 **로그인 토큰**을 다룬다. 이런 민감 정보가 암호화 없이 오가면 중간에서 가로채질 수 있다. 그래서 HTTPS가 필수다.

- **Let's Encrypt**: **무료**로 HTTPS 인증서를 발급해 주는 기관. `certbot` 도구로 발급·자동 갱신.
- **80 → 443 리다이렉트**: 사용자가 실수로 `http://`(80포트)로 들어와도 **자동으로 안전한 `https://`(443포트)로 돌려보낸다.**
- 80포트는 인증서 갱신용 통로(ACME 챌린지)와 리다이렉트만 담당하고, 실제 서비스는 443이 처리한다.

---

## ⑥ 결과·배운 점

- **실서비스 가동**: `https://beautalk.site`로 누구나 접속하는 실제 서비스가 되었다.
- **작은 서버에 알뜰하게**: 메모리 1GB 한 대에 세 서비스를 메모리 한도로 잘게 나눠 안정적으로 운영.
- **안전한 운영**: HTTPS 자물쇠 적용, 시크릿은 `.env`로만 주입(커밋 0건).
- **배운 점**: 제약(메모리 1GB)이 곧 설계의 기준이 된다. "프론트는 서버에서 빌드 안 한다", "상자마다 메모리를 나눈다" 같은 결정이 모두 이 제약에서 나왔다.

### 명세서 F1305(배포·심화) 충족 포인트

| 요구 | 우리가 충족한 방식 |
|---|---|
| 외부 접속 가능한 배포 | AWS EC2 + 도메인 `beautalk.site` 실서비스 |
| 컨테이너 기반 | Docker Compose 3서비스(db·backend·nginx) |
| 보안 적용(심화) | Let's Encrypt HTTPS, 80→443 리다이렉트, 시크릿 `.env` 분리 |
| 안정적 구성 | Nginx 리버스 프록시, 메모리 한도 튜닝, 수동 마이그레이션 |
