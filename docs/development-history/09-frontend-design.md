# 09. 프론트엔드와 디자인

## ① 한 줄 요약

화면을 **Vue**로 만들고(조립식 부품처럼), 화면 이동은 **라우터**, 데이터는 **Pinia**가 들고 있게 나눈 뒤, 로그인 안 한 사람을 문 앞에서 막고(가드) 출입증이 만료되면 알아서 새로 받아 끼우게(자동 갱신) 했으며, 색·간격·글꼴을 **디자인 토큰**으로 묶어 **모바일 우선·일관된 화면**을 만든 단계입니다.

---

## ② 무엇을 했나 (쉽게)

용어부터 한 줄씩 풀어 두겠습니다.

- **SPA(단일 페이지 앱)** = 페이지를 통째로 새로 받지 않고, 필요한 부분만 바꿔 끼워 빠르고 매끄럽게 움직이는 웹앱.
- **컴포넌트** = 화면을 이루는 조립식 부품(버튼·카드·목록 등). 한 번 만들어 여러 곳에 재사용.
- **상태(Pinia)** = 로그인 정보처럼 여러 화면이 같이 봐야 하는 데이터를 한곳에 모아 두는 보관함.
- **라우터** = 주소(`/community` 등)에 맞춰 어떤 화면을 보여 줄지 정하는 길 안내.
- **라우터 가드** = 로그인 안 했으면 들어가는 문 앞에서 막는 경비.
- **JWT(디지털 출입증)** = 위조 못 하게 서명된 출입증. 요청할 때마다 내밉니다.
- **디자인 토큰** = 색·간격·글꼴을 변수로 정해, 한 곳만 바꾸면 전체가 바뀌게 한 규칙.
- **반응형** = 화면 크기(폰·PC)에 맞춰 레이아웃이 자동으로 바뀜.

### 기술 스택

| 도구 | 역할 (쉽게) |
|---|---|
| Vue 3 (`<script setup>`) | 화면 부품을 만드는 틀 |
| Pinia | 데이터 보관함(상태 관리) |
| Vue Router | 주소에 맞춰 화면 바꾸기 |
| Vite | 코드를 모아 빠르게 빌드·실행 |

전체 화면은 약 13개입니다(채팅·둘러보기·커뮤니티 4종·마이페이지 4종·로그인·온보딩 등).

---

## ③ 왜 이렇게 했나 (선택지 비교)

### 비교 1 — 아이콘: 이모지 vs 커스텀 라인 아이콘

| 방식 | 장점 | 단점 |
|---|---|---|
| 이모지 (🙂❤️🔍) | 따로 만들 필요 없음 | 기기·OS마다 모양·색이 제각각, 디자인 톤이 깨짐 |
| **커스텀 라인 아이콘 (우리 선택)** | 어디서나 같은 모양, 우리 색에 맞춤 | 직접 그려야 함 |

→ **커스텀 라인 아이콘**을 택했습니다. 이모지는 같은 ❤️라도 아이폰·안드로이드·윈도에서 다르게 보여, 차분한 디자인 분위기를 망가뜨리기 때문입니다.

### 비교 2 — 스타일: 인라인 스타일 vs 디자인 토큰

| 방식 | 설명 | 문제 |
|---|---|---|
| 인라인 스타일 | 부품마다 색·간격을 그때그때 직접 적음 | 같은 "크림색"이 화면마다 미묘하게 달라지고, 색을 바꾸려면 수십 군데를 다 고쳐야 함 |
| **디자인 토큰 (우리 선택)** | 색·간격·글꼴을 변수로 한 번 정의해 모두가 그 변수를 씀 | 처음에 토큰 체계를 설계해야 함 |

→ **디자인 토큰**을 택했습니다. `base.css` 한 곳에 색·그림자·둥글기·글꼴을 변수로 정해 두면, 한 줄만 바꿔도 전체 화면이 같이 바뀝니다. 일관성과 유지보수, 둘 다 잡습니다.

## ④ 어떻게 만들었나

### Vue SPA 구조 (부품·보관함·길 안내)

세 가지로 역할을 나눴습니다.

- **컴포넌트(부품)** — 화면을 작은 부품으로 쪼개 재사용합니다. 글 카드, 토스트 알림, 확인 다이얼로그 등.
- **상태(Pinia 보관함)** — 로그인 정보(출입증) 같은 공용 데이터를 한곳에 모아, 어느 화면에서든 같은 값을 봅니다.
- **라우팅(길 안내)** — 주소마다 어떤 화면을 띄울지 정합니다. 화면 코드는 필요할 때 불러오게(지연 로딩) 해서 초기 로딩을 가볍게 했습니다.

### 라우터 가드 — 문 앞의 경비

들어가는 모든 길목에서 먼저 검사합니다.

- **`requiresAuth`(로그인 필요)** — 로그인 안 한 사람이 채팅·커뮤니티·마이페이지 등에 들어오려 하면, 문 앞에서 막고 `/login`으로 돌려보냅니다.
- **`guest`(비로그인 전용)** — 이미 로그인한 사람이 다시 로그인 화면에 가려 하면, 본 화면(`/chat`)으로 돌려보냅니다.

→ 사용자가 "빈 화면에 들어갔다가 튕기는" 어색한 경험을 미리 차단합니다.

### 자동 토큰 갱신 — 끊김 없는 사용

모든 요청에 출입증(JWT)을 자동으로 붙이는 **API 래퍼**(`services/api.js`)를 한 곳에 뒀습니다.

```
[요청에 출입증 자동 첨부]
        │
        ▼
[출입증 만료(401)?] ──아니오──▶ [정상 처리]
        │ 예
        ▼
[출입증 조용히 새로 받기] ──▶ [원래 요청을 자동으로 다시 시도]
```

- 출입증이 만료돼도 사용자는 **로그아웃되거나 끊기지 않고** 하던 일을 이어 갑니다.
- 여러 요청이 동시에 만료를 만나도 **갱신은 딱 한 번만** 하도록 묶어, 중복 갱신이나 잘못된 로그아웃을 막았습니다.

### 디자인 시스템 — "Botanical Editorial"

차분하고 잡지 같은(에디토리얼) 분위기를 목표로 잡았습니다.

- **색·질감** — 크림색 배경에 세이지(연녹)·로즈(연분홍) 포인트. 모든 색을 `base.css`의 **토큰 변수**로 관리합니다.
- **글꼴** — 제목은 세리프(Fraunces / Noto Serif KR)로 무게감을, 본문은 읽기 편한 산세리프로.
- **제목 크기 통일** — 모든 페이지 제목을 `.t-page` 하나로 맞춰, 화면마다 제목이 들쭉날쭉하지 않게 했습니다.
- **반응형** — 모바일을 먼저 설계하고, 넓은 화면(900px 이상)에서만 살짝 키우는 단일 분기 방식.
- **디테일** — 스켈레톤 로딩(내용이 뜨기 전 회색 뼈대), 카드 등장 애니메이션, 아치형 제품 이미지 프레임, 전역 토스트·확인 다이얼로그.

### 접근성·UX 배려

- **모달은 Teleport로 처리** — 팝업을 화면 맨 바깥(body)에 띄워, 다른 요소에 가려지는 z-index(겹침 순서) 문제를 없앴습니다.
- **움직임 줄이기 존중** — 기기에서 "애니메이션 최소화"를 켠 사용자에게는 화면 움직임을 줄여 줍니다(`prefers-reduced-motion`).

---

## ⑤ 결과

- Vue 3 + Pinia + Vue Router + Vite로 약 13개 화면의 SPA를 완성했습니다.
- 라우터 가드와 자동 토큰 갱신으로 **로그인 흐름이 끊김 없이** 매끄러워졌습니다.
- 디자인 토큰·단일 타입스케일·반응형으로 **모바일 우선의 통일감 있는 UI**가 완성됐습니다.
- 이모지 대신 커스텀 아이콘, 인라인 스타일 대신 토큰을 택해 **일관성**을 확보했습니다.
- 화면 수 기준 명세서 **NF1304(페이지 5개 이상)**를 충족했습니다.
